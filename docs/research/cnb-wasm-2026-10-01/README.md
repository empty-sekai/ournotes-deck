# Draft CNB CLI / browser WASM research build

This build makes the existing current-core recommendation experiment runnable as a JSON CLI and a browser Worker session. It reuses the current score, power, Snap and payoff implementation at `4e1f1ce31be60d08dafda149b22fd258c4ca6761`. It is a research Draft. Latest-game modeling, player objectives/search approval, screenshot recognition and a production MoeNotes integration remain gated by [MoeNotes #12](https://github.com/StarMoe-org/moenotes/pull/12).

The existing numerical source changes are imports of a shared monotonic search clock and visibility of `normalized_objective`. Candidate contexts are rebuilt with the existing `FiniteSeedContext::simulate`; no older `rebind` / `simulate_declared` scheduler was migrated. The added recommendation module is an experimental search/transport adapter, not a completed formal GoalSpec or legality resolver.

The new CLI accepts DeckData, roster and request files; the WASM session accepts their original JSON text. Typed request, constraint and judgement-stream fields reject unknown or duplicate fields, and the corpus preserves integer weights above JavaScript's safe-integer range. All explicitly supplied network confirmations and finished-frame inputs, including null and empty arrays, return Unsupported. Request fields are never silently removed to fit the older simulator.

CNB performed Rust 1.88 locked builds, formatting, Clippy with two documented exceptions for unchanged baseline warnings, 272 existing core tests, the adapter preflight test and synthetic fixture export, then CLI / Chromium WASM parity on 28 raw UTF-8 inputs. These are current-core synthetic tests, not ARM64 game-native comparisons. [Build summary](build-summary.json) binds versions, locks/source identity, artifact hashes and the bounded scope; [compiled source](compiled-source.json) records all 124 files, unchanged before and after the build. [Browser acceptance](browser-acceptance.json) records the individual cases. The PR's additional documentation is outside that compiled-source manifest.

Deadline result counts may differ across hosts. Every retained candidate is complete for the declared atoms and agrees with the same-input uncapped oracle; partial candidates do not enter Top-K. Hard cancellation terminates the entire Worker. A fresh Worker starts a fresh session. This synchronous adapter does not implement incremental step/resume or a streamed incumbent.

Formal input resolution still needs to separate confirmed ownership, selectable cards and unknown progression. Legacy roster types can ignore unknown keys and supply progression defaults; Power resolution can lack a reachable Snap rank binding. Duplicate-character search requirements describe an empty feasible search domain, whereas an illegal fixed physical deck requires rejection. The research boundary does not authenticate an account or certify the latest game's full legal domain.

Build and wrapper usage are described in [the WASM adapter README](../../../wasm/recommend/README.md). The synthetic exporter can be run on CNB with `BDON_FIXTURE_OUT` set to an output directory. This manual exporter is ignored by the default test suite and was separately executed in the reported 274 test invocations. No generated binaries or game payloads are checked into this PR.

[The archived execution scripts](../../../tools/research/cnb-wasm-2026-10-01/build-owned.sh) are the exact CNB harness used for these observations. They expect the documented Docker container names, a Git checkout at the fixed source directory, the pinned browser/tool dependencies and `/workspace/cache/member-owned-current4e-20261001`. The corpus and browser scripts reproduce the 28 transport cases after the fixture export and build. They are a research recipe with explicit environment assumptions; they do not install a MoeNotes endpoint or update the published engine.
